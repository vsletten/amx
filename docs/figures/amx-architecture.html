amx · Agent Mail Exchange — give agents an address, not an API

Email already has delivery, retry, backpressure, DNS federation, verified identity, threading and a durable record. amx keeps the mail server as-is and adds one small gateway.

DNS you already own: MX  ·  SPF  ·  DMARC p=reject  ·  one DKIM key per agent (revoke an agent = delete one record)  ·  agent card pointer
Unmodified mail server off the shelf
Postfix + Dovecot today, Stalwart next. Accepts and sends SMTP, queues and retries for days, keeps mailboxes people can open over IMAP. Nothing in it is patched.
2amx gateway the product
One small service on the server's three standard hooks. Policy is decided before any agent code runs on an untrusted message.
Ingress · policy
at the SMTP transaction (milter)
  • Verify the sender's per-agent signature
  • Validate the JSON part against its schema
  • Agent busy → 450 try later; the sender's server retries by itself
  • Bad message → 550 + reason; never stored
  • Optional content judge: injection? parts agree?
Delivery · invoke
over LMTP
  • Delivery is invocation: the message is handed straight to the agent's handler
  • The handler's result is the reply: done, retry later, or bounce
  • A copy lands in a real mailbox a person can open
  • No polling, no webhooks
Outbound · hold queue
authenticated submission
  • Signs with the agent's own key; per-agent rate limits
  • Hold rules (commits money, new domain, tainted input) file the mail in Outbox/Held
  • A person approves it from any mail client; only then is it signed and sent
Journal · record
append-only, hash-chained
  • Every message in and out, SHA-256 chained to the previous entry
  • Tampering is detectable; duplicates are handled once
  • amx trace <task> tells one task's story end to end
3Your agents
Python SDK handler or MCP tools, in your own runtime. An agent receives a message as data and sends a reply; it never speaks SMTP and never sees a key.

Another organization running amx
Their agents have verified identities and speak the same message profile. Tasks, states and schemas travel in headers and a JSON part. No shared platform, no exchanged API keys: addressing is DNS MX.
People on Gmail, Outlook, a phone
They see the plain-text part and hit Reply. The reply comes back to the right task because the correlation token lives in the address itself (agent+t_8f3a2c@…), which survives every client and every forward.
Any existing mail system
Legacy business systems, ticketing, mailing lists, hosted "agent inbox" products. If it can send an email, it can talk to your agent. Four billion mailboxes need nothing installed.
What it is not
Not a new wire protocol, not low-latency, not a replacement for A2A or MCP. It is the cross-organization, offline-tolerant, human-inspectable transport those protocols lack.
